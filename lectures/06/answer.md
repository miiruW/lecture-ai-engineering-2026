## 1. 第3回と第6回の違い

第3回では、Pythonで実装した関数をAIエージェントに直接登録していた。

第6回では、MCPサーバーが公開しているツールを取得し、AIエージェントから利用する仕組みに変更された。

| 比較項目 | 第3回 | 第6回 |
|---|---|---|
| ツールを選択する | AI | AI |
| ツールの登録 | Python関数を直接登録 | MCPサーバーから取得 |
| ツールの呼び出し | Python関数の呼び出し | MCP経由 |
| 外部機能の追加 | 個別に連携処理を用意する | 既存のMCPサーバーを利用できる |

**MCPによって変わったのは、AIにツールを提供する仕組みであることが理解できた。**

## 2. AIエージェントとMCPクライアントの違い

| 構成要素 | 役割 |
|---|---|
| LLM | 質問を理解し、利用するツールや回答内容を判断する |
| AIエージェント | モデルの呼び出し、ツールの実行、結果の確認など、処理全体を進める |
| MCPToolset | AIエージェントとMCPクライアントを仲介する |
| MCPクライアント | MCPサーバーとの通信を担当する |
| Transport | HTTPや標準入出力などの通信手段 |
| MCPサーバー | ツールやデータを提供する |
| JSON設定ファイル | サーバーの接続先や起動方法を定義する |

**MCPクライアント自体はAIエージェントではないことが理解できた。（受講当初は混乱していたため、理解を深めたという意味で）**

## 3. API連携とMCP連携の違い

外部サービスのAPIを直接利用する場合、APIの仕様を確認し、リクエスト処理やレスポンス処理、AIエージェントへのツール登録などを個別に用意する必要がある。

一方、既存のMCPサーバーを利用する場合、サーバーの提供者が実装した連携処理を再利用できる。

APIを利用するタイプのMCPサーバーは、以下のような機能をまとめた「コミコミパック」と考えると理解しやすいと感じた。

- APIとの通信処理
- レスポンスの処理
- ツールの名前・説明・引数の定義
- MCPという共通規格に対応した接続窓口

## 4. MCPを利用するメリット

Pythonで統計解析や検定を行う際、アルゴリズムを一から実装せず、SciPyなどの外部ライブラリを利用することがある。

MCPも、他の開発者が実装した便利な機能を再利用できるという点が、外部ライブラリを利用する感覚に近くメリットであると感じた。

## 5. MCPは必ず利用したほうがよいのか

当初、自前のPython関数をMCPサーバー化するメリットがあまり理解できなかった。

自分のPythonプログラムだけで利用する小規模な機能であれば、関数を直接呼び出すほうがシンプルな場合もある。

MCPのメリットが大きくなるのは、複数の外部サービスを利用する場合や、自作した機能を他のAIアプリケーションでも利用したい場合である。

MCPを導入すると通信処理や依存関係、セキュリティなどの管理も必要になるため、目的に応じて使い分けることが重要だと理解した。

## 6. 講義や課題を通しての気づき

MCPはAIそのものを賢くする技術ではなく、AIが利用できる機能を増やしやすくするための技術である。

AIエージェントが必要なツールを判断し、MCPクライアントがサーバーと通信し、MCPサーバーが実際の機能を提供するという役割分担を理解できた。

また、AIエージェントの開発では、すべての機能を自分で実装するだけでなく、既存の便利な機能を組み合わせ、AIに適切に使わせるという設計も重要であると感じた。
