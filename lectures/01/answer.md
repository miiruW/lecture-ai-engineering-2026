# 第1回 解答

## 演習

- リポジトリを fork した
- Python の実行環境と API キーを設定した
- `ask.py` を使って質問を実行した

## 宿題

- 取り組んだレベル：基礎
- やったこと：同じ質問を複数のGeminiモデルに対して実行し、回答内容の違いを比較した。
gemini-3.5-flash-lite
gemini-3.5-flash
gemini-3.1-flash-lite

- 結果：
gemini-3.5-flash-lite

3回の実行における出力トークン数は615、637、657であり、比較的安定していた。
いずれもLoRAの基本概念、必要とされる背景、メリット、活用事例を説明しており、回答の構成にも大きな違いはなかった。
特徴的だったのは、「付箋」「追加のノート」「プラグイン」といった比喩を使い、専門知識が少ない人にも理解しやすい説明を重視していた点である。

gemini-3.5-flash

3回の実行における出力トークン数は828、661、731であり、flash-liteよりも回答量の変動が大きかった。
基本的な説明内容はflash-liteと共通していたが、従来のフルファインチューニングとの比較や、具体的なGPUの例、LoRAの組み合わせなど、より実用的な情報が含まれていた。
また、「辞書と補足ノート」という比喩を使い、従来の学習方法とLoRAの違いを段階的に説明していた。

gemini-3.1-flash-lite

3回の実行における出力トークン数は735、781、704であった。

基本的な説明構成は他のモデルと類似していたが、2回目と3回目の回答では「低ランク行列」「行列の分解」「2つの小さな行列」といった技術的な説明が含まれていた。
特に3回目の回答では、LoRAの仕組みを単なる比喩だけでなく、行列の計算という観点から説明していた点が特徴的だった。
一方、1回目は初心者向けの説明が中心であり、同じモデルでも実行ごとに技術的な説明の深さが異なっていた。
モデルの新旧や名称だけでは、説明の詳しさを単純に判断できないことがわかった。

- 気づき・疑問：
今回の実験を通じて、モデルの違いは単純な回答速度や文章量だけでなく、説明の方向性や技術的な深さにも表れることがわかった。

一方、同じモデルでも回答が変化するため、1回の実行結果だけでモデルの性能を判断するのは難しいと感じた。
古いモデルでも技術的な説明に触れている部分もとても興味深かった。
（新しいモデルだからと言って必ずしも技術的な説明が多いとは限らない）

また、今回は3回という少ない試行回数及びtemperatureの変更は行っていない環境下での比較であるため、回答の安定性を定量的に評価するには、試行回数の増加やパラメータの変更による評価も行う必要があると考える。
